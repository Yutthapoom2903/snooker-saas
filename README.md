# Cue — ระบบร้านสนุ๊กเกอร์ (multi-tenant)

ระบบกลางให้หลายร้านใช้ร่วมกัน: ลูกค้าดูโต๊ะว่างและจองผ่าน LINE, พนักงานเปิด/ปิดโต๊ะและสแกน QR,
เจ้าของร้านดูรายรับ/ออกรายงาน PDF, บอร์ด ESP32 ที่โต๊ะแสดงเวลาและนับคะแนน

```
apps/api            NestJS 11 + Prisma 6 (SQLite) + MQTT broker (Aedes) ในตัว   :3001 / :1883
apps/web            Next.js 15 + Tailwind 4                                     :3000
hardware/firmware   ESP32 PlatformIO (env esp32dev = ใช้งานจริง, hwtest = ทดสอบฮาร์ดแวร์)
hardware/simulator  จำลองบอร์ดใน terminal (ใช้ก่อนของมาถึง)
docs/mqtt-contract.md   สัญญาข้อความระหว่าง server กับบอร์ด
```

## เริ่มใช้งาน (localhost)

```bash
# ครั้งแรก (เครื่องในออฟฟิศมี SSL inspection → ต้องใช้ CA ของระบบ)
export NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt
npm install
cp apps/api/.env.example apps/api/.env      # แล้วเปลี่ยน JWT_SECRET / QR_SECRET เป็นค่าสุ่มยาวๆ
cd apps/api && npx prisma db push && npm run db:seed && cd ../..

npm run dev        # api + web พร้อมกัน
```

## Flow การจอง

1. ลูกค้าเปิด `/s/<ร้าน>` → เห็นโต๊ะว่าง/ไม่ว่าง live + ฟอร์มจอง → กด **จองผ่าน LINE**
2. เปิด LIFF ใน LINE → ล็อกอิน LINE อัตโนมัติ (ไม่ต้องพิมพ์ส่งอะไร) → bot ส่งการ์ดมัดจำ + เงื่อนไขไม่คืนมัดจำถ้าสายเกิน 15 นาที
3. ลูกค้าสแกน PromptPay + แนบสลิป → ระบบอ่าน QR บนสลิป (สลิปที่เคยใช้แล้ว = ปฏิเสธทันที)
   - ร้านเปิด **ตรวจสลิปอัตโนมัติ** (EasySlip / SlipOK): ตรวจกับธนาคารว่าเข้าบัญชีร้าน ยอดครบ โอนหลังกดจอง → ผ่านครบ **ยืนยันเองทันที**
   - ไม่ผ่าน / ไม่ได้เปิด / บริการล่ม → การ์ดไปกลุ่มพนักงาน (มีเหตุผล) ปุ่ม **ยืนยัน / ปฏิเสธ**, หลังร้านมี badge + เสียงเตือน
   - รอเกิน 10 นาที → เตือนซ้ำในกลุ่ม + เจ้าของร้าน; ถึงเวลาจองแล้วยังไม่มีใครตรวจ → ยกเลิก แจ้งลูกค้าติดต่อขอเงินคืน
4. ยืนยันแล้ว → ลูกค้าได้ QR (ใน LINE + หน้าตั๋ว) — สแกนได้ตั้งแต่ 30 นาทีก่อนเวลา ถึงสาย 15 นาที
5. เลยเวลา → ระบบ mark ไม่มา, QR ใช้ไม่ได้, ยึดมัดจำ (cron ทุกนาที)
6. หน้าร้านสแกน QR ที่ **สแกน QR เช็คอิน** → บันทึกว่ามาถึง (มัดจำปลอดภัย) → กด **เริ่มจับเวลา**; ถ้าโต๊ะที่จองยังไม่ว่าง เลือกย้ายโต๊ะได้
7. ปิดบิล: มัดจำหักจากค่าโต๊ะ ถ้ามัดจำมากกว่าบิล ระบบบันทึกทอนคืนเป็นเงินสด
8. คืนมัดจำเมื่อยกเลิก: เจ้าของร้านเท่านั้น

ลูกค้า walk-in: พนักงานกด **เปิดโต๊ะ** ที่หน้า **โต๊ะในร้าน** ได้เลย

**ยังไม่เชื่อม LINE = โหมดทดลอง:** ทุกขั้นทำงานบนเว็บ, ข้อความที่จะส่งไป LINE ดูได้ที่ หลังร้าน → **กล่อง LINE** (กดปุ่มยืนยันในการ์ดได้)

### เชื่อม LINE จริง
1. LINE Developers: สร้าง Messaging API channel (OA ของร้าน) + LINE Login channel → เพิ่ม LIFF (endpoint `<PUBLIC_URL>/s/<slug>/liff`, scope `openid profile`)
2. localhost ต้องมี URL https สาธารณะ: `cloudflared tunnel --url http://localhost:3000` แล้วตั้ง `PUBLIC_WEB_URL` ใน `apps/api/.env` เป็น URL นั้น
3. Webhook URL: `<PUBLIC_URL>/api/line/webhook/<slug>`
4. ใส่ค่าทั้งหมดที่ หลังร้าน → ตั้งค่าร้าน → LINE; เพิ่ม bot เข้ากลุ่มพนักงาน พิมพ์ `ไอดี` แล้วใช้ ID นั้นเป็น "ผู้รับการแจ้งเตือน"

## เวลาเปิด-ปิด / วันหยุด

ตั้งค่าร้าน → เวลาเปิด-ปิด (ปิดหลังเที่ยงคืนได้) หรือ **เปิด 24 ชั่วโมง**, จองล่วงหน้าได้กี่วัน (default 14),
หยุดประจำสัปดาห์, วันหยุดพิเศษ. หน้าจองแสดง chip วันใกล้ๆ + ปฏิทิน บอกวันเต็ม/เหลือน้อย/ร้านปิด.
ช่วงหลังเที่ยงคืนก่อนร้านปิด "วันนี้" = คืนนี้ของร้าน (จองรอบดึกได้)

## คิดเงิน

- ราคาต่อชั่วโมงต่อโต๊ะ, คิดตามเวลาจริงปัดขึ้นทีละ 15 นาที ขั้นต่ำ 30 นาที (ปรับได้ต่อร้าน)
- ส่วนลดไม่ซ้อน: ระบบเลือกอันที่ลดมากที่สุดระหว่างส่วนลดสมาชิกกับแคมเปญที่ใช้ได้ ณ เวลาเปิดโต๊ะ
- ราคาที่ใช้ = ราคาตอนเปิดโต๊ะ (แก้ราคาแล้วมีผลกับโต๊ะที่เปิดหลังจากนั้น)
- รายรับ = ค่าโต๊ะที่เก็บ + มัดจำ + ค่าสมาชิก − คืนเงิน

## ข้อควรรู้ก่อนขึ้น production

- SQLite เหมาะกับ dev/ร้านเดียว; ขึ้น cloud หลายร้าน → เปลี่ยน `provider` ใน `schema.prisma` เป็น `postgresql` แล้ว `prisma db push`
- กันจองซ้อน: `createDraft` ล็อกแถวของร้าน (`UPDATE "Shop" SET "id" = "id"`) ก่อนเช็กโต๊ะว่าง → การจองของร้านเดียวกันวิ่งทีละรายการ ใช้ได้ทั้ง SQLite และ PostgreSQL (READ COMMITTED) — ถ้าย้ายไป PostgreSQL แล้วอยากกันที่ระดับ DB ด้วย ให้เพิ่ม exclusion constraint (`btree_gist`, `EXCLUDE USING gist (tableId WITH =, tstzrange(startAt, endAt) WITH &&)`) ซึ่งต้องคิดเรื่อง draft ที่หมดอายุ (`DRAFT_HOLD_MIN`) ก่อน เพราะ constraint ไม่รู้จักเวลาหมดอายุ
- MQTT ตอนนี้เป็น TCP ไม่เข้ารหัส (1883) ใช้ใน LAN ร้านเท่านั้น; ข้ามอินเทอร์เน็ตต้องใช้ TLS (8883)
- Session ล็อกอินอายุ 12 ชม. (cookie httpOnly) ยังไม่มี refresh token
- Rate limit ของหน้าสาธารณะเป็น in-memory (process เดียว)
- สตรีมวิดีโอแต่ละโต๊ะ + สมัครเข้าชม = Phase 2 (`SnookerTable.streamUrl` เตรียมไว้แล้ว)
- พนักงาน login ผ่าน LINE: ทำหลังเชื่อม LINE OA จริง (ต้องมี LIFF)
- ตรวจสลิปอัตโนมัติมีค่าบริการต่อสลิปตามผู้ให้บริการ — เช็คราคา/quota ก่อนเปิดใช้
